# anchor 分片:一步步验证正确性 + 开大 maxlen/anchor 指南

**日期:2026-07-22**
关联:[[speculators-npu-dsv4-status]]、`my_docs/2026-07-20_dspark训练显存与更大模型可行性.md`(§三·补)、`my_docs/2026-07-22_usp适配文档.md`

> **本次实现了什么**:DSpark 的 anchor 分片跨卡扩容。同一 SP 组的卡持有同一条 base 序列,各自只算 `1/sp` 的 anchor 块;主导显存 `T×V` ÷sp,`max_anchors` 可 ×sp。**默认 `--sp-size 1` 时全部恒等,行为不变。**
>
> **正确性保证**:锚点块条件独立(mask 已证实)→ 分片 = 标准数据并行,可证明等价单卡。核心 helper 已本地双 rank 实测通过;下面教你在集群上把整条链路验掉。

**原理**:loss 是"对有效位取平均"(`sum/count`)。分片后各卡是不相交子集,分子/分母要分开求和再除。做法:backward 用 `loss × (sp × local_count / Σcount)` 缩放,保持全局 DDP 平均即等价单卡;sp=1 系数=1。

## 步骤 2:sp=1 回归(必须与现状**逐位一致**)

在你集群 1 张卡上,同一数据/种子,对比 `不加 --sp-size` 和 `--sp-size 1`:
```bash
# A: 现状
torchrun --nproc_per_node=1 scripts/train.py <你现有参数> --seed 1234 --log-freq 1 --epochs 1  2>&1 | grep -i 'loss'
# B: 显式 sp=1(应与 A 每一步 loss 完全相同)
torchrun --nproc_per_node=1 scripts/train.py <你现有参数> --sp-size 1 --seed 1234 --log-freq 1 --epochs 1  2>&1 | grep -i 'loss'
```
**判据**:A、B 前若干步 loss **逐位相同**。不同 → sp=1 的恒等守卫被破坏(不该发生,来找我)。

## 步骤 3:sp=2 == sp=1 数值等价(核心正确性验证)

这是**真正证明分片正确**的一步:同一条序列、同一组 anchor,sp=2 分两卡算,规约后的 loss/梯度应与 sp=1 单卡一致。

```bash
# 参考:sp=1 单卡,max_anchors=512(全 512 个 anchor 在一张卡)
torchrun --nproc_per_node=1 scripts/train.py <参数> --sp-size 1 --max-anchors 512 \
    --seed 1234 --deterministic-cuda --log-freq 1 --epochs 1  2>&1 | grep -iE 'train.*loss|ce_loss|tv_loss'

# 测试:sp=2 两卡(dp_size=1,同一条序列,各算 256 个 anchor,分片)
torchrun --nproc_per_node=2 scripts/train.py <参数> --sp-size 2 --max-anchors 512 \
    --seed 1234 --deterministic-cuda --log-freq 1 --epochs 1  2>&1 | grep -iE 'train.*loss|ce_loss|tv_loss'
```
**判据**:两次的 `ce_loss / tv_loss / loss` 前几步应**数值一致**(bf16 + 通信算子,容许 ~1e-2 内的浮点差)。
- 一致 → **分片 + 规约在真实模型上等价单卡**,anchor 分片正确。
- 明显不一致 → 说明某处系数/采样/计数对不上,**别放量**,把两边前 3 步的 loss 贴给我定位。

> 说明:`--sp-size 2` 时 2 卡组成**1 个 SP 组**(dp_size=1),数据 loader 让两卡拿同一条序列;`select_anchors` 采样 512 个后由 rank0 广播、各取 256。所以 sp=2 的"总 anchor 集"== sp=1 的 512 个。需要 RNG 确定(`--seed` + `--deterministic-cuda`);若你的 set_seed 按 `seed+rank` 播种,rank0 的采样恰好等于 sp=1 单卡的采样。

## 步骤 4:显存与扩容(开大 maxlen/anchor,换 full attention)

验完等价性,再测"能省显存 / 能开大"。**关键:`--max-anchors` 是全局值,每卡实际处理 `max_anchors/sp`。**

### 4.1 显存 ÷sp(固定全局 anchor,加 sp)
```bash
# 单卡 max_anchors=512(基线显存)
torchrun --nproc_per_node=1 ... --sp-size 1 --max-anchors 512
# 2 卡 max_anchors=512(每卡 256 → 每卡显存应明显低于基线)
torchrun --nproc_per_node=2 ... --sp-size 2 --max-anchors 512
```
看 NPU 显存:sp=2 每卡应显著低于 sp=1(主导 `T×V` ÷2)。

### 4.2 开大 anchor(你要的效果:global anchor ×sp,每卡显存回到基线附近)
```bash
# 2 卡,全局 1024 anchor(每卡 512,和单卡 512 的显存相当,但覆盖 2× anchor)
torchrun --nproc_per_node=2 ... --sp-size 2 --max-anchors 1024
```

### 4.3 换 full attention + 开大 maxlen
DSpark 默认全层滑窗;换 full attention 让后置 anchor 看全前缀:
```bash
    --full-attention-indices 0 1 2 3 4     # 5 层全 full attention(按需)
    --total-seq-len 8192                    # 拉大 maxlen
    --sp-size 8 --max-anchors 4096          # 8 卡分片,全局 4096 anchor
```
> ⚠️ full attention + 大 S 下,复制的 `verifier_logits [1,S,V]` 会变大——**先上"方案 C(verifier_logits 只在 anchored 位算)"** 干掉它,maxlen 才能真开大(见显存文档 §三)。要我接着做方案 C 就说。

**健康判据**(放量前必看,配 `--logger tensorboard`):
- `train/tv`、`train/ce` 有限且下降;
- `train/eal` > 1 且上升;
- sp 越大、per-rank 显存越低,但 loss 曲线形状应与单卡一致(等价性已在步骤 3 验过)。

## 已知限制 / 注意

1. **`--max-anchors` 需能被 `sp_size` 整除**(否则分片不均;`shard_anchors` 按 stride 切,余数会让各卡差 1 个,统计上无害但破坏步骤 3 的严格一致——验证时取整除值)。
2. **`--sp-size` 必须整除 world_size**;建议 `sp_size ≤ 每节点卡数`(anchor 分片只在 SP 组内 all-reduce loss,放节点内更快)。
3. **日志里的 loss 标量**在 sp>1 下是"各卡均值再平均",数值上略糙(cosmetic);**训练本身正确**(backward 用的是缩放后的 loss,`train/*_acc`、`eal` 走 `_sum/_total` 全局求和、是准的)。
4. **梯度规约**沿用现有全局 DDP/FSDP 平均;`anchor_loss_scale` 已把它校正为等价单卡(步骤 1 的 grad 测试已证)。用 HSDP(`--fsdp-shard-size`)时同理。
5. **未在 NPU 上验证过**:核心 helper 本地双 rank 通过,但整条模型链路(步骤 2-4)需你在集群上跑一遍确认。**步骤 3 是闸门——它过了才放量。**
