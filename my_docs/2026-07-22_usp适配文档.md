## 0. 目标 & 为什么

**目标**:给 speculators 的 DFlash/DSpark 训练加 **Ulysses 序列并行(SP)**,把序列维 `S` 切到 `sp_size` 个 rank 上,从而**在同样单卡显存下把可训练上下文提升 ~sp_size 倍**(或塞更多 anchor)。

**为什么省显存/提升上下文**:把 `S` 切成 `sp_size` 份后,每个 rank 只持有 `S/sp_size` 的:输入 `hidden_states`、`verifier_last_hidden_states`、`verifier_logits`,以及 `~A/sp_size` 个 anchor(anchor 从本地分片采样)。→ **主导显存(anchor×vocab 那堆)近似缩 sp_size 倍**。sp_size=8(节点内)理论上 2048 → ~16k。

**⚠️ 关键前提**:DSpark 默认 sliding_window=2048。USP 拉长总 `S`、分摊显存,但**每个 anchor 实际仍只注意其窗口内**——想让单 anchor 看得更远,需同时放宽窗口/用 full_attention。所以 USP 的准确收益是"**更长文档 + 更多 anchor + 显存分片**",不是"单 anchor 看更远"。

**与其他手段正交叠加**:词表裁剪(4.75×,零成本)、activation checkpointing、分块 TV loss 都可与 USP 叠加。USP 是"真要长上下文"时的重炮,建议先上零成本手段。

## 1. 现状(重要:地基已埋一半)

`src/speculators/train/distributed.py` **已有 SP/DP 进程组脚手架**,但**完全没接线**:
- `_init_sp_process_groups(rank, world_size, sp_size)`:**连续 rank → SP 组、跨步 rank → DP 组**(Ulysses 需要的拓扑);
- getter 齐全:`get_sp_group / get_dp_group / get_sp_size / get_sp_rank / get_dp_size / get_dp_rank`;
- **但**:`train.py:466 maybe_setup_distributed()` 没传 sp_size(恒 1)、无 `--sp-size` CLI、模型/注意力里**零 all_to_all**。

即"有人起了 SP 的头、没实现机制"。本适配就是把这套接起来 + 补齐机制。

specforge 参考要点:
- 序列分片:每 rank 持 `hidden_states[:, :usp_chunk_size]`;
- all-to-all 注意力(yunchang,`attention_backend="usp"`);
- **DSpark 稀疏全局位置 gather**:anchor 的 block label 全局位置可能在别的分片,用 `all_reduce(SUM)` 汇总各 rank 持有的那部分(`dspark.py:_gather_by_global_positions`);
- loss/metrics 在 sp_group 上 `all_reduce`。

## 2. 总体设计

### 2.1 拓扑(复用现有脚手架)
`--sp-size N` → `maybe_setup_distributed(N)`。world_size = dp_size × sp_size。SP 组内 `sp_size` 个 rank 共享**同一条数据、不同 seq 分片**;DP 组间是不同数据。梯度 all-reduce 走 DP 组(FSDP/DDP 要相应用 dp_group,而非全局)。

### 2.2 序列分片(dataloader)
- 同一 SP 组的 `sp_size` 个 rank 拿到**同一条 packed sequence**,各自取第 `sp_rank` 段(`S/sp_size`)。
- batch sampler 现在按**全局 rank** 分片数据 → 改为按 **dp_rank** 分片(SP 组内不切数据、只切序列)。
- 记录每段的全局 position 偏移(anchor 的全局位置计算要用)。

### 2.3 Ulysses all-to-all 注意力(核心新件)
标准 Ulysses:进注意力前对 `[b, s_local, H_full, d]` 做 `all_to_all(scatter=heads, gather=seq)` → `[b, s_full, H/sp, d]`,本地对完整序列、部分头做注意力(SDPA),再 `all_to_all(scatter=seq, gather=heads)` 还原。
- **NPU**:all_to_all 走 HCCL;本地注意力用 SDPA(Ascend 支持)。**yunchang 是 GPU/flash-attn 取向,不直接搬,照它的模式在 SDPA 外包 all_to_all。**
- 要求 `H_full % sp_size == 0`(Qwen3-32B: 64 heads / 8 = 8,OK;GQA 的 KV heads=8 / 8=1,OK)。
- 自动微分:all_to_all 的 backward 是 scatter/gather 互换。

### 2.4 DSpark anchored 全局位置 gather
DSpark 的 anchor block 预测**全局位置**的 token,label/hidden 可能在别的分片。照 specforge `_gather_by_global_positions`:每 rank 把自己持有的全局位置填进局部缓冲,`all_reduce(SUM, sp_group)` 汇总。`select_anchors` / `get_base_indices_for_anchored_blocks` 需感知全局偏移。

### 2.5 loss / metrics 规约
per-position loss 求和后在 **sp_group** 上 `all_reduce(SUM)`,分母(有效 token 数)同样规约,再相除。参考 `UspAdapter.reduce_loss/reduce_metrics`。

## 4. 正确性风险 & 验证

1. **默认行为**:sp_size=1 必须与现状逐位一致(每 stage 都留 sp=1 恒等路径)。
2. **all_to_all 正确性**:`scatter_seq_gather_heads(gather_seq_scatter_heads(x)) == x`;gather 后本地序列==全序列。Stage 1 单测覆盖。
3. **数值一致性**:sp=k 训练的 loss/grad 必须≈单卡(通信不改数学)。Stage 2/5 用小样本对齐。
4. **DSpark 全局位置**:gather 错=target 错位、静默训歪。Stage 4 必须对齐单卡。
5. **滑窗限制**:见 §0——USP 不放宽单 anchor 视野。
6. **NPU**:HCCL all_to_all + SDPA 本地注意力;`H % sp_size == 0`;跨节点 all_to_all 慢,**建议 sp_size≤8 限节点内**。
7. **梯度归属**:开 SP 后参数梯度 all-reduce 应走 **dp_group**(不是全局),否则 SP 组内重复平均。Stage 5 处理。
