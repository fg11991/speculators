# 910B 环境与训练上手指南(镜像 / 单测 / Qwen3 训练)

> 更新:2026-07-14,配套分支 `npu-support`。调研依据见文末链接。

## 1. 用什么镜像,去哪下

**推荐镜像(serve 侧与训练侧共用一个)**:

```bash
# 910B(Atlas A2 系列,单机 8 卡)
docker pull quay.io/ascend/vllm-ascend:v0.22.1rc1

# 910C 集群(Atlas A3 系列)用 a3 变体
docker pull quay.io/ascend/vllm-ascend:v0.22.1rc1-a3

# 国内拉 quay.io 慢的话,加代理或用 openEuler 变体同 tag:
#   v0.22.1rc1-openeuler / v0.22.1rc1-a3-openeuler
```

**镜像内组件版本**:

| 组件 | 版本 |
|---|---|
| vLLM | v0.22.1 |
| vllm-ascend | v0.22.1rc1 |
| torch | 2.10.0 |
| torch_npu | 2.10.0 |
| CANN | 9.0.0(含 NNAL 9.0.0)|
| Python | 3.12(镜像默认;3.10/3.11 亦支持)|

**版本下限与理由**:`extract_hidden_states` 的昇腾实现(`AscendExtractHiddenStatesProposer`,vllm-ascend PR #8799)**自 v0.20.2rc1 才进入**;v0.18.0 稳定版和 v0.19.x 都没有,不能用。推荐 v0.22.1rc1 而非 v0.20.2rc1,因为它额外带了 DFlash serving(含多模态)、GLM5.2/DSv4 支持与刷新过的 spec-decode 文档。

**训练侧兼容性**:torch 2.10.0 满足 speculators 的 `torch>=2.9,<=2.12.1`,直接在同一镜像里源码装 speculators 即可,不必单独做训练镜像。

**宿主机前提**:Ascend 驱动/固件按 CANN 9.0.0 兼容性表核对(`npu-smi info` 能看到 8 张 910B 卡)。

## 2. 启动容器

```bash
docker run -itd --name speculators-npu --net=host --shm-size=64g \
  --device /dev/davinci0 --device /dev/davinci1 \
  --device /dev/davinci2 --device /dev/davinci3 \
  --device /dev/davinci_manager --device /dev/devmm_svm --device /dev/hisi_hdc \
  -v /usr/local/dcmi:/usr/local/dcmi \
  -v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi \
  -v /usr/local/Ascend/driver/lib64/:/usr/local/Ascend/driver/lib64/ \
  -v /usr/local/Ascend/driver/version.info:/usr/local/Ascend/driver/version.info \
  -v /etc/ascend_install.info:/etc/ascend_install.info \
  -v /root/.cache:/root/.cache \
  -v /data:/data \
  quay.io/ascend/vllm-ascend:v0.22.1rc1 bash
```

要点:按需增删 `--device /dev/davinciN`(上面给了 0~3,vLLM 2 卡 + 训练 2 卡);`--shm-size` 给足(dataloader 多进程);把模型/数据盘挂进去。

## 3. 安装 speculators(npu-support 分支)

```bash
docker exec -it speculators-npu bash
git clone https://github.com/fg11991/speculators.git -b npu-support
cd speculators
pip install -e . --no-deps        # 镜像里已有 vllm/torch/torch_npu,别让 pip 动它们
pip install datasets safetensors  # 缺什么补什么,唯独不要动 torch/vllm 系
```

装完自检:

```bash
python -c "import torch, torch_npu, speculators; print(torch.__version__, torch.npu.is_available())"
```

## 4. 跑单元测试

```bash
pip install pytest
# 训练侧核心(必须全绿;2026-07-14 在分支上为 139 passed, 9 skipped)
python -m pytest tests/unit/train -q
# 全量
python -m pytest tests/unit -q
```

已知说明:
- `9 skipped` 是多卡 GPU 测试(`requires_multi_gpu`,CUDA 判定),NPU/CPU 环境跳过是预期行为;
- `tests/unit/utils/test_loading.py` 里有若干用例要**在线下载 HF 模型**,内网/无 HF 凭据会报 401/网络错——是环境问题不是代码问题,可加 `--deselect tests/unit/utils/test_loading.py` 排除;
- 训练侧改动(#755/#711/timer)对应的用例在 `tests/unit/train/test_draft_config_init.py`、`test_setup_model.py`、`test_step_timer.py`。

## 5. 910B 上启动 Qwen3-8B 训练

### 5.1 先探测 vLLM 抽取链路(最重要的一步)

```bash
export ASCEND_RT_VISIBLE_DEVICES=0,1   # 注意:置空字符串≠未设置,一律显式赋值
python scripts/launch_vllm.py Qwen/Qwen3-8B \
  --target-layer-ids 2 18 33 \
  -- --data-parallel-size 2 --port 8000
```

起来后拿任意 prompt 打一次 `/v1/completions`,确认 hidden states 文件落盘。这一步通了,整条链路就没有硬阻塞。

### 5.2 一键脚本

```bash
bash examples/train/dflash_qwen3_8b_sharegpt_online_npu.sh
```

脚本做三件事:`prepare_data.py`(CPU)→ 起 vLLM(NPU 0,1)→ `torchrun` 训练(NPU 2,3)。首次建议把 `MAX_SAMPLES` 改成 500、`EPOCHS=1` 冒烟,再放 5k。

### 5.3 关键参数与回退梯子

| 情况 | 处理 |
|---|---|
| 默认注意力后端 | 分支在 NPU 上自动 flex→`sdpa`(脚本里也显式传了)|
| sdpa 在你的 CANN 版本报算子错 | `--draft-attn-impl eager`(纯 eager + 稠密 float mask,最保险)|
| muon 优化器异常 | `--optimizer adamw`(脚本里有 `OPTIMIZER_ARGS` 开关)|
| 多卡分布式策略 | **默认 DDP**(#711 之后);draft 单卡放得下就别加 `--fsdp-shard` |
| 单卡放不下(更大 draft)| 加 `--fsdp-shard` |
| MTP 训练 | ❌ 强制 flex attention,NPU 暂不支持 |

### 5.4 训练后检查

```bash
# 混合精度缺陷 canary:已训 checkpoint 的 norm 张量 max|w-1| 恰为 0 即命中(需重训)
python scripts/check_norm_canary.py ./output/dflash_qwen3_8b_sharegpt_npu/checkpoints
```

指标预期:loss 稳定下降,EAL / per-position acceptance 与 GPU 参考值同量级。历史上(修 #711 之前)训出的 checkpoint 一律先跑 canary 再决定要不要复用。
